# 任务分流

先判断任务类型，再只读取该类型需要的来源。

| 任务类型 | 必读来源 | 主要交付物 | 验收方式 |
|---|---|---|---|
| 查询现有规则 | `CONTEXT.md`、项目适配层、指定知识来源 | 带来源的事实说明 | 事实、历史和未知项可区分 |
| 讨论新玩法 | `governance.md`、相关领域资料 | 决策记录或设计草案 | 未决选择已标出，必要问题已确认 |
| 需求可视化 | `governance.md`、`prd-rules.md`、已确认需求和项目上下文 | 可编辑流程图、UI 原型、确认记录 | 用户确认流程、状态、界面区域和操作落点 |
| 创建或交付 PRD | `governance.md`、`prd-rules.md`、相关项目上下文 | 仅含最终确定需求的 PRD | 准入条件满足，完成草稿、自审、修订和复审后输出或写入 |
| 修改已确认 PRD | 原 PRD、`prd-rules.md`、变更来源 | 更新后的 PRD；正文外的修订记录 | 全文旧口径已清理，正文只保留最终需求；未决选择先询问用户 |
| 创建本地任务 | `issue-tracker.md`、来源文档 | `.scratch/issues/*.md` | 状态、验收、下一步完整 |

只有资料无法确定、且会改变方向的选择才需要询问用户。

PRD 的规则、数值、口径冲突或方案取舍不清时，按 `prd-rules.md` 先询问用户；用户确认前停止正式文档生成和写入。

需要创建 PRD 时，先走“需求可视化 → 人工确认 → PRD”阶段。流程图和 UI 原型未确认时，PRD 任务停留在可视化阶段。
