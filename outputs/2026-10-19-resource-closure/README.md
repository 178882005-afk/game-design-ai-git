# 统一资源账与梦灵逐日模型 · 接手 README

更新：2026-10-19。适用情景：2026-10-10 新服、四层正常全勤、D1–D365。

预算上限为非R／小R／中R／大R每月0／100／1000／5000元，**每月10日重置、余款不结转**。继承原采购账的固定名义价值策略，不假设花满预算；钻石收入保留，本轮不执行额外钻石采购。主线是输入的参考轨迹，不会因算得的新属性自动向前推进。

招募路径明确选用原交接的`5001＋6001`。现行配置也有`5901＋6901`：新心愿入口1109按累计消耗100招募券开放，旧入口227按招募等级2开放，不能将两条路径的奖励相加。这里核实的是所选路径的配置与索引执行逻辑，目标区服实际使用哪条入口仍未验证。

## 先看结论

**原先的“缺少统一库存入口”和“缺少招募／许愿联合过程”已经补成可重跑的条件模型。**已有免费来源、付费领取、额外刷关、招募奖励、星妙之路、许愿、积分兑换和梦灵升级通过同一份库存连接；装备／研究也从这份库存扣金币。

**整库全部来源和全部养成操作仍没有闭合。**这次接通了已纳入供给的资源和梦灵主链，不代表符文实装、洗练、载具、公会等全部操作已得到正式标准进度。下面把完成范围和剩余范围写清楚。

本模型没有要求用户补充已有资料能求出的数据。查配置就能确定的规则已落实；玩家实际选择、战斗成绩和运行服是否按配置执行，不能从静态配置唯一推回。

## 1. 一条链读懂计算

```text
已有四层逐日轨迹、活动和购买账
       ↓ 所有收入按日期／玩家层／道具ID只入账一次
共享库存：体力、金币、钻石、招募券、水晶、积分、图纸、特饮、碎片等
       ↓
体力刷关 → 招募券 → 十连／保底／额外抽 → 本体／重复碎片／特饮／金币／积分
                     ↓ 招募等级＋星妙进度
                  功能开放／候选变化／星妙本体与资源／累计兑换水晶
                     ↓
水晶＋合格九格 → 五次完整领取 → 本体／碎片／特饮／金币／积分
                     ↓
积分按周兑换碎片；同职业特饮均分 → 持有与升级
                     ↓
新增金币与原金币合流 → 装备强化／武器研究 → 期末库存
```

每天每种道具都核对：`期初＋本日收入－本日消耗＝期末`。认领来源、容器穿透和养成消耗都有明细。

## 2. 本次实际补上的规则

| 环节 | 计算方式 | 为什么影响结果 |
| --- | --- | --- |
| 随机能量特饮5103001 | 自动消耗箱体，按七职业各1/7展开期望数量 | 主线已有大量特饮来源，过去没有流入梦灵升级。 |
| 常驻5001 | 每10张券立即十连；顺序池优先于循环保底；额外抽固定节点优先，固定0保留0 | 不能把抽数统一乘一个额外倍率。 |
| 奖励筛选 | 一次十连及其额外抽使用抽前拥有／累计获得状态；池内计数随抽取更新 | 同一请求中新得到的本体不能提前改变其他槽候选。 |
| 招募等级 | 当前划断每十连经验10；额外抽不增加经验；升级后清理招募计数；7/8级检查D35门槛 | 同样的总券数，在不同等级／服龄会使用不同池。 |
| 星妙之路 | 10/10新服适用10031–10036；按十连进度、逐阶段领取与结转推进 | 有确定本体和材料，不能只看随机池获得梦灵。 |
| 等级累抽奖励 | 1级池累计23次十连奖励1110100，只领一次 | 增加一条确定本体获取路径。 |
| 招募累计兑换 | 许愿功能开启后的十连每10次兑换1水晶；领取后扣除已兑次数 | 水晶供给和招募进度相连；开启前的抽数不倒补。 |
| 许愿6001九格 | 按当前池逐格生成；单批max_num限制参与生成；只接受含当前可抽最高品质梦灵的批次 | 九格不是九次独立同分布抽取。 |
| 完整领取 | 按3/2/2/1/1五次领取，合计5水晶；固定积分1500、金币500 | 水晶、合格批次共同限制完整轮数。 |
| 刷新 | 每天最多1次广告刷新；整批领完后的新批另算；合格批资源不足时保留 | 刷出一批不等于当天能领一批。 |
| 本体／碎片 | 首次本体只激活一次；重复本体按道具转换率入碎片；碎片激活先扣成本 | 防止把首次激活等价碎片再记成库存。 |
| 兑换／升级 | 已拥有且解锁的五折商品，周一清限购；高品质优先，同品质预算均分；职业特饮按同职业已持有梦灵均分，不足份额结转 | 所有兑换和升级从同一物理库存扣除。 |
| 共享金币 | 招募、许愿及星妙金币合并后重算装备优先／研究后置情景 | 原来装备结果不能直接与新增梦灵结果相加。 |

职业特饮的分配份额、积分的分配份额只是库存的预留记录，不能再当成一份新资源。模型沿用梦灵产销“普通碎片＋职业特饮”基准；通用替代材料仍留库存。

## 5. 哪些已经能求，哪些还不能唯一求

| 状态 | 内容 | 接下来如何处理 |
| --- | --- | --- |
| 已求出 | 已纳入来源的统一库存、招募／许愿联合奖励过程、星妙／累抽／兑换、梦灵逐日持有和普通材料升级、装备与研究共享金币 | 从本交付直接接手；无需再问用户规则。 |

| 还需模型接线 | 符文ID／排重／合成与装配，装备和秘宝洗练，载具同套零件／金币，藏品转换与增产，其他自动容器及主题招募 | 配置已有相当部分。继续查所有权与转换规则后，在这份库存执行消费；不能把原独立上界叠加。 |
| 不能从静态配置唯一反推 | 金币副本实际击杀金币、挑战满血结果、真实选择及目标服部署状态 | 要给“真实玩家”结果需对应运行记录；给“条件模型”可明确选择上下界／操作策略后算。 |
| 原任务已留待核 | 十线之外的公会、任务、卡带、外观等每日状态及完整面板分母 | 继承既有约束，保留空值；不把子集占比包装成完整面板或跨线最优。 |

目前**不需要用户再整理一份材料清单或提供基础概率表**。现有数据足够继续做条件模型。真正不能由配置解决的是“发生过什么”和“玩家选什么”，不是公式缺失。完整真实标准进度与全局最优仍未达成，本页不把它们标为完成。

## 7. 后续AI如何继续

1. 先读本页和知识库根README；按`资源来源与消耗覆盖.tsv`定位剩余接线，不把缺来源写成0。
2. 核当前SVN、配置与本轮指纹，重新读变更记录；这里的版本不是永远最新。
3. 本轮输入继承`.scratch/progression_20261017/supply、gaps、purchase_portfolio`，计算入口是本目录`_work/build_closure.py`；`_work/inspect_current.py`读取当前配置，`_work/validate_closure.py`做规则边界核验。
4. 计算按“外部来源→转换→招募/许愿→共享材料消费→其他模块消费→结余”推进；所有新增操作必须从相同库存扣款。现金购买与钻石购买、条件副本上界不隐式合并。
5. 保存抽样数、随机种子和删失样本；至少复核首个十连、等级切换、D35、周一、许愿满批、重复本体及负库存。
6. 新结果单独出版本。原20本静态表、既有46页工作簿和原看板仍保留，不能拿其旧终点充当本模型结果。

本轮核验：70,434条外部来源，183,015条具体样本逐日账，35,040条梦灵逐日结果；20项规则边界及12项独立导出核验通过；全部4×128×365日库存核验未出现负库存或守恒失败。最大逐日浮点残差1.46e-11。
