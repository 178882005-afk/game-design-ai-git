# 梦境数值知识库说明

从整体逻辑到文件用法 · 2026-10-19 · SVN 阅读版本 r65364

## 1. 三分钟看懂：这份库在做什么

**这是一套把《梦境护卫队》的成长设计、资源账和设计依据放在一起的数值工作资料。** 它既保存“玩家怎样变强”，也保存“变强需要什么、资源从哪里来、现有供给能支持到哪里”。交接文档负责说明规则、设计理由与未完事项；Excel 负责保存具体对象、参数、公式和测算结果。[资料依据：R0、R1、R2]

读懂它，只需先抓住三个问题：

- **成长目标**：提升哪个对象？升到哪一级、哪一星或哪个节点？得到属性、机制还是更多资源？
- **实现路径**：用哪些材料？从哪些玩法、商店、活动获得？开放条件和次数是多少？
- **资源约束**：一天拿到多少、花掉多少、还能剩多少？金币、钻石、体力等共享资源够不够？

这三个问题分别对应养成表、产销表，以及两者之间的预算与进度关系。词典让它们使用一致的道具、属性、单位和价格。

### 一条贯穿全库的逻辑

玩家处于某个开服日和成长阶段 → 等级、主线进度决定可用入口 → 入口产生资源 → 资源分配到各条养成线 → 养成带来属性、机制或增产 → 支持后续推进。

这里的箭头表示**业务关系**。各表已经保存了这条链的许多环节，但尚未全部接成一个统一、自动联动的逐日模型。[R2 §11；R3 §2–3]

### 先记住五句话

| 要点 | 含义 |
| --- | --- |
| 词典统一语言 | 道具按 ID 对齐，属性按单位换算，效果和属性分开。 |
| 养成表给规则与成本 | 回答升一次怎样变化、需要多少材料。 |
| 产销表给来源与测算 | 回答资源从哪里来、按某个场景能支持什么进度。 |
| 交接文档给依据与边界 | 解释为什么这样设计、哪些说法已过时、哪里还缺证据。 |
| 现有结果要带场景阅读 | 极限日产出、试算等级、随机期望和线上实际进度分别判断。 |

## 3. 数据如何串起来

### 3.1 词典：给全库建立共同语言

项目词典有三类业务词典和三张装备价值矩阵。

| 内容 | 负责什么 | 使用时注意 |
| --- | --- | --- |
| 属性词典 | 中文属性名、程序字段、业务单位、换算倍率与叠加规则 | 设计表中的百分数和程序整数先换单位，再比较。 |
| 效果词典 | 中文机制、效果编号、所属模块 | 效果编号不等于属性编号；有编号不代表已完成战斗价值计算。 |
| 道具词典 | 道具ID、历史别名、钻石/人民币价值、来源与获取途径 | 名称便于阅读，ID用于对账；价格空白可能是明确暂不定价。 |
| 装备价值系数 | 等级×品质的系数 | 同一等级横看品质，纵看等级成长。 |
| 装备分解价值 | 用于经济产销的装备价值 | 按基准6钻与系数计算，四舍五入为整数。 |
| 装备展示价值 | 用于展示的装备价值 | 是分解价值的5倍，汇总经济账时不再加一遍。 |

词典中“全局暴击伤害”的业务单位为百分比，换算倍率为100。例如设计值1.4%对应程序数值140。先看单位才能判断两个值是否相同。[W00／属性词典 A3:E3；R1 §2、§7]

部分系统表保留局部“道具词典／价值引用”。它们方便计算和追溯，**不保证每项价格都自动跟随主词典更新**。跨表汇总时要按道具ID、单位和当前确认口径再核对。[W00及各工作簿的价值页；R4 §4.1]

### 3.2 单本 Excel：从输入到结果

多数工作簿的结构可以这样读：

字段字典定义含义 → 核心参数和业务参数驱动计算 → 业务页保存规则与结果 → 总览便于审核，校验提示缺项和异常。

| 页面或字段 | 怎样理解 | 怎样维护 |
| --- | --- | --- |
| 字段字典 | 说明字段角色、单位、中文公式、主键和校验规则 | 先理解它，再修改数值。 |
| 核心参数 | 全局标量输入，如观察天数、预算比例、次数或价值锚点 | 按参数名称定位，保留当前确认值。 |
| 标识字段 | 对象ID、等级、星级、品质、部位等 | 决定记录是哪一个业务对象。 |
| 设计参数 | 调整模型的入口 | 多数用黄色辅助识别；黄色公式也可能由上游驱动。 |
| 计算字段 | 公式算出的成本、收益、累计或进度 | 回到输入修正，避免直接覆盖结果。 |
| 校验字段 | 对主键、范围、单位、引用、守恒等作检查 | “通过”只覆盖这项检查的范围。 |
| 设计/审核总览 | 把关键数字放在同一视图中比较 | 规则要求总览不承担参数，也不反向驱动业务页。 |

这描述的是维护规范。现存工作簿保留了不同年代和不同模型的结构：总览不一定都排第一；藏品产销的多个页面是分区矩阵；载具产销有抽样结果。应按实际字典和页面读取。[R1 §1–8；W10–W27]

**数据状态会影响计算。** 多数养成表的“已确认／待确认”都参与计算，但“待确认”只是带未决条件的试算；“占位／停用”不参与。部分产销表还使用“暂定”“测算假设”等状态，须看本表字典与公式。价格空白、真实零值、未开放时的零产出，也分别有不同含义。[R1第64–84行]

## 4. 十份养成表：玩家通过什么变强

### 4.1 玩家等级：整套成长的进度坐标

**推进对象**是玩家等级。经验让玩家从当前等级走向下一等级，等级又关系到系统开放和成长上限。

表内有1–300级经验曲线；“等级预期”以开服天数×非付费、小额、中额、高额四类玩家组织1200条记录。它将每日经验累计，再从经验曲线查出计算等级；目标最低/最高等级是另一组输入。当前不少目标区间空白，校验显示参数缺失。[W10／玩家等级、等级预期 A1:I6；R2 §2]

关键语义：玩家 N→N+1 的经验成本读**当前N级行**；升到N级的累计经验则是此前各级成本之和。不要把“当前级成本”和“已到当前级的累计成本”混用。

### 4.2 梦灵：单个对象成长与全局收益并行

**推进对象**是24名梦灵的拥有状态、等级和等级节点。主要投入是本体碎片和职业特饮。

本体碎片限制单个梦灵的推进；职业特饮连接同职业多个梦灵的预算。超能特饮是执行侧替代资源，不能让每个梦灵都重复占用同一份材料。[W11／梦灵基础、职业特饮映射、升级消耗曲线；R2 §3.1]

交接口径区分三层属性：基础属性、升级产生的全局属性、当前等级节点属性。全局属性来自已拥有梦灵，不要求上阵；等级节点读取最高已解锁节点的完整快照，旧节点不继续相加。设计表中的“品质强度模型”用于解释和比较，也不能当作程序直接放大基础属性的公式。[R2 §3.2–3.3]

### 4.3 梦灵招募：把获取过程拆成规则

**推进对象**是招募等级、奖池状态、保底计数与获得的梦灵/碎片。工作簿拆成招募等级、奖池、奖池内容、保底、活动招募等页。

读奖池时先看资格与有效候选，再看基础权重和保底。展示权重只服务展示；常驻十连、百连、固定额外奖励、随机追加和活动招募的规则需要分别读。百连在详细交接中按十个十连批次判断，不是简单把一个平均倍率乘100。[W12／设计总览 A2；R5 §6.3]

它回答“抽取过程有哪些规则”，实际一天能抽多少、何时获得某梦灵，还需要每日招募器、水晶、积分和活动来源。

### 4.4 梦灵皮肤：拥有收益与穿戴效果分开

表内有18款皮肤和90条皮肤星级记录。激活、升星消耗，当前星级属性和效果分别承载。

交接记载：皮肤激活后，拥有属性无需穿戴即可汇总；穿戴决定外观及相应效果。激活的备选材料方案和升星的替代材料有不同用途。不能只因名称同属“皮肤”，就把拥有属性和穿戴机制混成一种收益。[W13／梦灵皮肤、皮肤星级；R2 §3.4]

### 4.5 符文：随机获取、词条与保底共同影响成本

工作簿保留效果模型、本体、品质规则、档位权重、心愿洗练、心愿池和格子解锁。其重点是解释品质、部位、有效候选与洗练之间的关系。

普通洗练先筛候选，再按权重抽取；动态排除和保底会改变后续池子。传说/神话祝福石的心愿规则分别记录，不能用一次抽取的概率推完所有长期成本。交接还明确：`intercept`不能被当成服务端普通洗练的过滤保证。[W14；R2 §5]

表内既有待确认记录，也有业务校验不通过项，例如品质规则 S2、S3、S5。读取时应连同具体校验条件查看，不能概括为全表已验收。[W14／品质规则]

### 4.6 队长装备：换装、部位强化和洗炼是不同环节

基础属性由装备的等级×品质×部位决定；强化绑定六个部位，换装备保留部位强化。当前交接把旧梦灵装备与共鸣归为停用历史。

洗炼同时处理两套结果：**附加属性**和**效果词条**。可以锁已有的效果词条，附加属性仍整组重随机；锁定条也占效果数量上限。锁0/1/2/3条的成本倍率是1/3/9/27。[W15／装备基础属性、装备强化、附加属性池、附加词条池；R2 §6.1–6.2]

因此，评估一次洗炼不能只看“会不会出某条效果”，还要看锁几条、有效池、附加属性范围和材料成本。装备经济价值沿用分解口径，展示值单列。

### 4.7 秘宝：洗炼同时推动等级，技能另有成本

表内有12级、5孔、7套方案的规则。转运石既用于洗炼，也用于技能升级，但两种消耗的后果不同。

交接记载：成功洗炼实际消耗的转运石按1:1增加秘宝经验；技能升级不增加这份经验。当次洗炼先使用旧等级池生成词条，再增加经验并升级，新池从下一次操作使用。最高品质未命中计数按新生成词条累计，跨孔位和方案共享；达到门槛只是最高品质入池，仍按权重随机。[W16；R2 §7]

这条线同时包含资源预算、等级、技能和随机词条。单有“累计转运石”不能直接推出全部成长结果。

### 4.8 载具：全局基础、装配效果与套装分层

表内有21种零件、1260条零件等级记录、400条载具等级记录。零件激活/升级、载具本身升级和套装分别维护。

交接记载：所有已激活零件的当前基础属性汇总；当前方案最多装4件，装配后才提供对应效果属性与机制。各级属性是完整快照。载具套装一次取一套，先比较品质，再比较生效等级；套装匹配中的同一件零件不能重复满足需求。[W17；R2 §8.1–8.2]

载具 N→N+1 的升级成本读目标N+1级行，与玩家经验取当前级行不同。打造还涉及十连按旧工坊等级完成奖励、结尾再升级的批次规则，留给产销模型处理。[R2 §8.3–8.4]

### 4.9 藏品：升星与多套收益并行

表内有18件藏品×25星的450条升星记录。首次本体激活，重复本体转碎片；当前星级属性与节点机制分别承载。

藏品与载具的套装算法不同：**藏品多套可同时达成，同一藏品可以参与多套**，每套取全成员共同达到的最高档。不能用平均星级或星级之和决定套装档位。[W18；R2 §9.1]

消耗例子：从未激活到25星为680片等价投入，其中10片表示激活；若已经获得本体并激活，再升到25星是670片。金币另算，不能把首次本体又重复加成10片库存。[R2 §9.2；W18／升星曲线]

当前交接已将旧攻击系数1、1.1、1.2和“燃起来了”旧套装要求标为过时背景。重建时应读当前曲线与套装页，避免继承旧默认值。[R2 §9.2；R3 §2]

### 4.10 武器研究：沿前置关系推进的节点树

表内研究节点共420个，交接拆为360个小节点和60个大节点。金币是通用投入，织梦微尘主要承载小节点，潜能棱晶承载大节点；收益包括属性与机制。

读这条线时要同时看节点ID、前置关系、投入和收益，不能只按总价判断可否完成。当前设计取消研究时间；加速沙漏退出现行规划和产销预算，配置残留及历史回收另行追溯。[W19／研究节点；R2 §4、§13]

## 5. 八份产销表：资源怎样支撑成长

“产销”在这里指资源的**产出、消耗、转换、预算和成长支持能力**。它不只指商业售卖。

### 5.1 玩法产销：共同的资源来源底表

它覆盖体力供给与分配、400关主线首次/重复奖励、1200条挑战奖励、自然挂机、快速巡逻和容器转译。按来源保存数量，再做原始/穿透总览及已定价部分估值。[W20]

当前场景使用主线400关、巡逻400档；免费体力390、额外购买150，主线重复分配比例1、快速巡逻比例0。这是现存参数下的静态场景。400关各阶段的首通累计，以及400档的每日收益，不能直接拿来当开服首日收益。[W20／核心参数 C2:C4；体力分配 A2:P3]

总览中的“每日免费”“每日额外”“一次性”是不同列；“原始产出”与“穿透产出”是同一批奖励的两种观察方式。

### 5.2 武器研究产销：先核全节点成本与材料来源

节点消耗记录420节点的当档和累计成本；主线、挂机与其他入口记录金币、微尘、棱晶来源。它适合回答“整棵研究树需要什么”和“哪些渠道能供这些材料”。

交接记录的全节点基础成本为金币6,988,720、微尘307,368、棱晶420，总估值1,481,540钻。总成本是静态投入；若没有每日分配和节点可达性，不能把它解释成完成日。[W21／节点消耗；R2 §4]

### 5.3 符文产销：不同品质先统一数量口径

它将符文本体、材料、容器、合成、格子解锁和两类洗练分别核算。4个同品质同部位符文合成下一品质，于是普通等价数量依次为1、4、16、64、256、1024、4096。[W22／核心参数 C13:C20]

这适合跨品质核资源量，但“合计普通等价数量够了”不等于玩家已经拿到所需部位和词条。当前静态场景还使用主线/巡逻400档、巡航15难度及20次协助上限，应看作场景上界分析。[W22／核心参数 C2:C8]

### 5.4 装备产销：已经有365天进度轴

日进度轴先取主线锚点，计算新增关卡、体力占用、重复次数、累计经验、玩家等级和巡航难度。之后统计装备的来源、等级、品质、部位期望，再看强化、洗炼的供需。

它已经能回答“在本表场景下，某天可以获得多少某品质某部位装备，以及材料是否支持计划投入”。“拆解换算”用于潜在转换，表内校验明确禁止直接把全部潜在拆解量当实际供给。[W23／日进度轴、装备产出、数学校验 A19:G21]

当前缓存场景首日450体力，平日390；D365主线104、玩家137级。这些是本表输入与曲线下的模型结果，适合解释逻辑，实际开服预期需带场景复核。[W23／核心参数；数学校验 A4:G8]

### 5.5 秘宝产销：比较立即投入与活动期冲刺

它有365天双路径账：常驻/活动产出、累计可用资源、技能消耗、洗炼消耗、库存、秘宝等级与活动返还。两条路径分别记录“立即”与“冲刺”的结果。[W24／日进度轴 A1:AT3]

逻辑是同一批资源换一种使用时机，可能取得不同活动返还，再反过来支持成长。经验只来自洗炼消耗，技能成本要扣库存却不增加洗炼经验。

本表仍有待补公会供给，核心参数C23保存0并标待确认。这里的0表示这份基线暂未计入该来源，不能解释为玩家真实公会产出永远是0。[W24／核心参数 A22:G23]

### 5.6 载具产销：有抽样模型，部分参数改变后要重跑

它把日进度、每日资源、零件产出、阶段目标、供需对照和载具/零件消耗放在一起。抽样参数保存样本数20,000和固定随机种子20260909。

核心参数同时保存“参数值”“本次模拟值”和“生效方式”。样本、预算、发条使用比例、首期战令余期、首日星期等改变后需要重跑模拟；目标和价格等部分下游计算可即时重算。修改一个单元格并不保证所有抽样结果都更新。[W25／核心参数 A1:G20；数学校验 A2:E3]

开放要求在本表为开服至少22天且主线60关。当前时间轴注明第40天满足主线要求，因此“22天”不能直接写成固定开放日。首期战令余期14天、首日星期一仍是场景假设。[W25／核心参数 B4:B5、G5、B9:B10]

### 5.7 藏品产销：随机获取与定向兑换组合推进

它记录来源与预算、定向兑换、随机奖励、藏品预期、增产收益和逐星消耗。比较持续养成与原停购策略，按预算、价格、限购、开放条件计算实际能购买的份数，再加随机资源期望。

当前表将公会贡献与已覆盖钻石收入各划20%给藏品；并不意味着其他系统使用剩余80%就必然够。心梦收入尚待核验，实际预算比例留空；场景开服日期仍为2026-09-10，周/月刷新据此定位。[W26／来源与预算 B7、B17:B23]

“藏品预期”的页内说明明确写的是**期望材料支持星级**。这可以表示资源供给能力，不能当作随机玩家的平均星级。增产页还有“假设已拥有怦怦时刻”的条件对照，也不能用这份增产倒推必然获取日期。[W26／藏品预期 A4；增产收益 A4]

### 5.8 梦灵产销：静态底数已落表，逐日部分未完成

它有24名梦灵参数、碎片/特饮当级消耗、累计消耗、五折兑换、招募收支和模型口径。当前能核“目标等级总成本”和“商店额度”，不能直接给完整逐日获取与成长结果。[W27／模型口径 A2:B18]

## 6. 用五个例子理解最关键的计算

### 例子一：体力是资源预算，钻石价格是估值

交接保存的及时领取/消耗上界是：自然恢复240＋定时领取120＝360体力/日；广告再加30＝390；钻石购买再加150＝540。[R2 §10.1；W20／体力供给]

390×6＝2340经验/日，前提是这些体力全部用于已核会按消耗追加经验的玩法。若有闲置、恢复封顶或不同经验规则的入口，就要按真实使用计算。首次初始体力单独计入，不能每天重发。

1体力估值2钻，因此390体力可以估为780钻；这**不会变成780钻可用余额**。购买体力的钻石支出则按实际交换数量与价格记入货币账。[R4 §4.1；W20／玩法投入总览 A3:P3]

### 例子二：一只宝箱，只采用一层数量口径

玩法给1个1级成长宝箱：原始视图记1个箱子。穿透后可记金币1000、梦境招募器5等内部奖励；每项按容器转译页追溯。

汇总时选择原始箱子层或穿透道具层。如果把箱子估值和内部道具价值都加上，同一奖励就记了两遍。自选箱估值按候选组合最高价值，但选取策略未定时，数量账不能假设每种候选都获得。[W20／容器转译 A2:L3；R4 §4.2]

### 例子三：升级属性有“快照”和“增量”两种语义

梦灵等级节点的交接例子：寒冰射手10–29级读取相应节点关卡伤害1000，30级后读取2000。后者替换前者，不能算成3000。设计表分别表示10%和20%，需按词典倍率换算。[R2 §3.2；W11／等级节点属性；W00／属性词典 A4:D4]

同样，果冻少女5级节点空属性会清除前一节点减值。**空配置可以是规则本身，不一定是数据漏填。** 累计升级成本则恰好相反，应把正确级段的成本逐项求和。[R2 §3.2]

### 例子四：材料支持等级不等于随机玩家平均等级

教学假设：一半玩家得到0片，另一半得到20片，那么平均资源是10片。如果某节点需要10片，按平均资源查表可能显示可以到该节点，但真实情况是一半达不到，另一半超过它。

因此，先求资源期望，再查非线性的等级门槛，与逐个玩家算等级再求平均，会给不同答案。随机获取、合成、保底和激活都要看模型到底输出的是期望资源、达标概率还是平均状态。[规则依据：R2 §11；W24／核心参数 E2；W26／藏品预期 A4]

### 例子五：梦域巡航按耗票判奖励，身份简称不够

库内较新的规则摘要写“队长读captain_reward，队员读teammate_reward”；详细交接补充了队员使用门票的分支。本次代码索引核对得到更明确的判据：

| 条件 | 评级奖励分支 |
| --- | --- |
| ConsumeTicket为真 | captain_reward |
| 不耗票，仍有助战奖励次数 | teammate_reward |
| 不耗票，助战奖励次数用尽 | teammate_reward_limit |

这是本次**知识库索引事实**：项目/仓库`server`，相对路径`src/mod/event_pve/role_event_pve.erl`，第2451–2478行。目标区服运行状态未验证。做产销应按耗票与结算档取奖励，避免仅凭“队长／队员”称呼选错分支。[K1；R2 §10.3；R5 §5.2]

### 日常接手时的五步

1. **先定位对象**：按系统、道具ID和业务主键找表，避免仅凭名字匹配。
2. **读清字段语义**：单位、成本取行、快照/累计、状态参与规则。
3. **确认场景**：开服日期、玩家分层、关卡、玩法次数、预算、周期。
4. **追溯结果**：从总览回到业务页，再到参数和来源；共享材料只分配一次。
5. **判断是否够用**：区分缺输入、需重算、需重跑模拟和需代码/运行验证。

商业化还要保持基础估价和实付收益分开。库内有随机箱期望、自选箱最高组合价值、碎片折价等规则；“1攻击=100钻”的生效对象和条件边界仍待闭合，不能据此批量反推所有效果价格。[R4 §4.1–4.4]
