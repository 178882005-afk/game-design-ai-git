## 取证方法与可复查边界

1. **事件直接判定。**装备、秘宝、载具、藏品用 `升级前／升星前 < 目标 ≤ 升级后／目标星级`；研究用精确 `激活节点`。这些是新建角队列的首次**跨级操作**，前提是建角以来该动作无漏报、无导入既有状态。老玩家在查询窗中的第一个事件只能叫“窗内首次出现”。
2. **符文 ID 对照。**本地正式 [`F_符文_rune_data.xml`](<E:/x1/配置/trunk/xml_gy/normal/F_符文_rune_data.xml>) `符文配置` 的 55 前缀有效行共有 809 个：七位 ID 768 个，八位 ID 41 个；分别用末位、倒数第二位读品质，809 行都与配置 `quality` 一致。10/1–4 补充队列的 41,718 次穿戴／替换事件全部是 55 前缀；其[穿戴符文 ID 清单](growth_runtime_rune_ids_20261015.tsv)有 291 个不同 ID，**291 个都在正式配置且品质编码一致**。其他前缀不可照搬此规则。
3. **秘宝双重校验。**10/1–4 补充队列截至 10/14 用实际洗炼消耗累加到正式配置 6,000／18,000／58,000／138,000 门槛，得 2／3／4／5 级人数 **196／180／46／1**；直接读 `洗炼后.等级` 的跨级事件人数也完全相同。这是截至日的混合随访校验，**不是 D7 达成数**。**知识库索引事实**：Wiki `dg-server-engineering`、project `server`、`src/mod/captain_treasure/role_captain_treasure.erl:L811-L830,L518-L525` 中，洗炼消耗额会累入秘宝经验并重算等级；这是索引源码，不等于已经证明运行服部署同一代码。实测一致仅支持当前样本的计算。
4. **数据与配置版本。**StarRocks 操作日志 `version` 在样本中有 `v260928`、`v260929`、`v261012` 等值；这不是 SVN 修订号。当前成本与品质映射取 10-15 本地正式 XML，尚缺每服实际发布的 XML／服务端构建版本及生效日期。对老角色要处理道具／伙伴日志约 90 天留存和注册快照覆盖；不能把当前配置默认为其历史规则。
5. **日龄与删失。**SQL 用 `first_ts >= reg_ts AND first_ts < DATE_ADD(reg_ts, INTERVAL 168/336/600 HOUR)`；9/30 队列能完整看 D14，10/1–4 队列只能完整看 D7，9/15–18 队列能完整看 D25。不同队列的占比不可当成同一玩家从 D7 到 D14 的变化；仅 9/30 同队列两列可比较。10/1 建角角色按日历日虽然在 10/14 已经历 14 个日期，但还未全都经过 336 小时，故不报其 D14。
6. **样本代表性。**本次宽渠道、全服探针用于证明“能否取证”，未筛付费层、活跃天数、测试号、滚服或当前单一运营渠道。所有结果是角色维度聚合，不是实际商品效果或玩家购买后的提前天数。
